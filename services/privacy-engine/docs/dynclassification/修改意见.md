# dynclassification 模块全面分析报告

***


## 一、逻辑问题

### 1.1 icd10\_range 算子违反 MatcherOperator 协议（严重）

**问题描述：**
`MatcherOperator` 协议约定签名为 `(value, params) -> bool`，但 `icd10_range_matcher` 返回 `Tuple[bool, str, str]`。这导致 `engine.py` 中到处出现 `if matcher.operator == "icd10_range"` 的硬编码特殊分支（L239、L304、L311、L316、L333），严重破坏了算子插件化的设计初衷。

**风险：**
如果未来新增类似"动态等级"算子，需要在引擎中继续添加 `if` 分支。

### 1.2 NER 层硬编码 L3/L4/L5 等级（中等）

**问题描述：**
`funnel.py` `_run_ner()` 中实体→等级映射写死了 `"L5"`、`"L4"`、`"L3"`。当使用金融标准（C1~C4）时，这些等级 ID 在 `taxonomy.levels` 中不存在，`_resolve_level()` 调用 `max_level()` 会因 `valid=[]` 回退到 `default_level`，NER 标签实质上被忽略。

### 1.3 \_apply\_override\_suppression 白名单合并逻辑有缺陷（中等）

**问题描述：**
`engine.py` L407-L418：遍历 `override_tags` 时，若遇到第一条有白名单的规则设 `has_whitelist=True`，但紧接着遇到第二条无白名单的规则时直接 `break` 并清空。这意味着遍历顺序影响结果——如果无白名单规则排在有白名单规则之后，白名单逻辑被完全跳过。语义不够明确，建议文档化或改为"任一无白名单 → 全局压制"。

### 1.4 match\_target 判定逻辑对 AND 规则过于粗暴（低）

**问题描述：**
`engine.py` L272-L277：AND 逻辑下，只要规则定义中任一 matcher 的 target 是 `field_value`，整个标签的 `match_target` 就标记为 `field_value`，进而在 override 压制中获得豁免。但实际可能是 `field_name` matcher 命中而 `field_value` matcher 未命中（AND 要求全部命中才触发），此时豁免语义不够精确。

### 1.5 service.classify\_field() 每次请求创建新 Funnel 实例（低）

**问题描述：**
`service.py` `_build_funnel()` 每次调用都 `new ClassificationFunnel(...)`。虽然 Funnel 本身轻量，但在高 QPS 场景下产生大量短命对象。engine 已被 `ProfileLoader` 缓存，Funnel 亦可按 engine 缓存键复用。

## 二、代码问题

### 2.1 OperatorRegistry 类级单例影响测试隔离

**问题描述：**
`_operators` 是类变量，所有测试共享。测试中注册的 `concurrent_op_*`、`op_throws_error` 等算子会永久残留，可能影响后续测试的 `list_operators()` 断言或产生意外命中。缺少 autouse fixture 在测试后清理。

### 2.2 REST 路由全局单例 \_service 无线程安全保护

**问题描述：**
`routers/dynclassification.py` L29-L38：`get_service()` 使用 `global _service` 无锁懒初始化。在 Uvicorn 多 worker（线程模式）下存在竞态，可能创建多个实例。

### 2.3 keyword\_contains 的 use\_word\_boundaries 在归一化后失效

**问题描述：**
`operators.py` L201-L213：先将 value 归一化（去下划线、去空格），再用 `\b` 做单词边界匹配。但归一化后字符串已无空格/下划线，`\b` 边界几乎不会出现在预期位置。例如 `"User_Phone" → "userphone"`，此时 `\bphone\b` 无法匹配（因为 phone 不再是独立单词）。

### 2.4 evaluate() 中 str\_value 转换丢失 None 语义

**问题描述：**
`engine.py` L172：`str_value = str(value) if value is not None else ""`。当 value 为数字 `0` 或布尔 `False` 时，`str(0)="0"`、`str(False)="False"` 可能产生意外正则命中。

### 2.5 DomainTaxonomy 使用 extra="allow" 但 confidence\_policy 无类型约束

**问题描述：**
`models.py` L150：`confidence_policy` 通过 `model_extra` 获取，是 dict 而非 `ConfidencePolicy` 模型。service 层需手动 `ConfidencePolicy(**policy_data)` 转换，缺少 Pydantic 校验保护。

### 2.6 profile\_loader.py 热重载使用 mtime 精度不足

**问题描述：**
在 macOS（APFS 纳秒精度）和某些 NFS 挂载（秒级精度）上，快速连续修改可能无法被 mtime 检测捕获。`reload_interval_seconds` 默认为 0（无节流），但 `check_and_reload()` 在每次 REST 请求中被调用，高频 stat 系统调用有 I/O 开销。

## 三、文档问题

### 3.1 testing.md import 路径全部过期（严重）

**问题描述：**
`testing.md` L29：

```python
from engine.privacy.classification.operator_registry import OperatorRegistry
```

正确路径应为 `engine.dynclassification.operator_registry`。L52-L54 同样引用了不存在的 `engine.privacy.classification.taxonomy`、`configurable_engine` 等旧路径。

### 3.2 api\_reference.md REST 响应格式与实际不一致（严重）

**问题描述：**
文档 L156-L174 声明响应为：

```json
{"tags": [...], "maxLevel": "L3", "audit": {...}}
```

实际 `routers/dynclassification.py` L91 返回 `resp.model_dump(by_alias=True)`，结构为：

```json
{"fieldResult": {...}, "auditInfo": {...}}
```

字段名和嵌套层级完全不同。

### 3.3 api\_reference.md gRPC proto 声明缺少 confidence/engine\_layer 字段

**问题描述：**
文档中 `DynClassificationResponse` 仅有 `tags`、`max_level`、`audit_timestamp`、`engine_layer`，但实际 proto 和 gRPC 测试验证还包含 `confidence`、`needs_human_review` 等字段。

### 3.4 testing.md 中 evaluate() 返回值描述错误

**问题描述：**
文档 L83-L91 示例：

```python
tags = engine.evaluate("mobile_number", "13800138000")
assert len(tags) == 1
```

实际 `evaluate()` 返回 `Tuple[list[SecurityTag], list[SecurityTag]]`，直接 `len(tags)` 得到 2（元组长度），应为 `tags, suppressed = engine.evaluate(...)`。

### 3.5 testing.md 运行命令路径错误

* L103: `cd /path/to/PrivShield`（Linux 路径）

* L143: `pytest tests/test_classification*.py`（旧文件名），应为 `tests/dynclassification/`。

### 3.6 three\_layer\_funnel\_design.md 中 classify\_field 签名不完整

**问题描述：**
文档 L123 声明返回 `FunnelResult`，实际返回 `Tuple[FunnelResult, list[SecurityTag]]`。

### 3.7 ops.md 环境变量 RELOAD\_INTERVAL 默认值与代码不一致

**问题描述：**
文档声明默认 60，`profile_loader.py` L81 实际默认为 `"0"`。

## 四、测试问题

### 4.1 缺少金融标准（C1\~C4）端到端测试

**问题描述：**
所有 fixture 均使用 L1~~L5 体系。虽然 `test_dynclassification_coverage.py` 测试了 generator 解析 C1~~C4，但没有对金融 taxonomy 执行完整的 `classify_field()` → 验证返回 C 级标签的集成测试。

### 4.2 NER/LLM 层仅有 mock 测试，无降级路径覆盖

**问题描述：**
`test_funnel.py` mock 了 NER/LLM，但未测试：

* NER 返回非法 label 时的容错

* LLM `arbitrate()` 返回的 `final_level` 不在 `taxonomy.levels` 中时的行为

* NER 适配器 ONNX → ModelScope 降级链

### 4.3 OperatorRegistry 测试污染全局状态

**问题描述：**
`test_dynclassification_edge_cases.py` L26-L38 注册 50 个 `concurrent_op_*`，`test_dynclassification_coverage.py` L176 注册 `op_throws_error`，均无 teardown 清理。

### 4.4 缺少 evaluate\_batch() 与 classify\_table() 的边界测试

**问题描述：**
`evaluate_batch` 仅在 coverage\_final 中有一个空规则测试。`classify_table` 无独立测试文件，未覆盖空 rows、schema 与 rows 字段不匹配等场景。

### 4.5 热重载并发测试断言不充分

**问题描述：**
`test_dynclassification_edge_cases.py` L40-L96：reader 断言 `resp.field_result is not None`，但未验证分类结果正确性（如 level 是否为 L3）。reload 与 classify 并发时可能短暂返回空结果，测试未覆盖此窗口。

### 4.6 test\_dynclassification\_grpc\_and\_metrics.py 仅 45 行，覆盖不足

**问题描述：**
仅测试了 happy path 和环境变量读取。缺少：

* gRPC 请求 domain/standard 不存在时的错误处理

* Prometheus 指标值断言（仅 import 了 metric 对象，未验证计数）

## 总结

模块整体架构设计合理（三层漏斗 + 配置化引擎 + 算子插件化），代码注释详尽，测试覆盖面较广（10 个测试文件、107+ 用例）。主要问题集中在：

1. **协议一致性：** `icd10_range` 破坏了算子协议抽象，是最需要优先解决的架构债务
2. **多标准适配不完整：** NER 层硬编码 L 级等级，金融 C 级体系下三层漏斗实质退化为单层
3. **文档严重滞后：** `testing.md` 和 `api_reference.md` 的关键示例与实际代码不匹配，会误导接入方

### 二十三、问题 7.1 详细分析

**根因**：`DynClassificationService` 中 `_ner_adapter` 和 `_llm_adapter` 为全局单例（避免重复加载模型），`_build_funnel()` 中通过 `if self._ner_adapter is None` 判断是否需要初始化。但 `reload()` 仅清除了 `_funnel_cache` 和 loader 缓存，未重置适配器。

**影响**：用户修改 taxonomy YAML 中的 `ner_model_path`、`ner_label_mapping`、`llm_classify_prompt_template` 等配置并触发热重载后，新配置不会生效，仍使用旧适配器的参数。

**修复**：
```python
def reload(self) -> None:
    self.loader.invalidate_cache()
    self._funnel_cache.clear()
    # 重置 NER/LLM 适配器（全局单例），使新 taxonomy 配置生效
    self._ner_adapter = None
    self._llm_adapter = None
```
