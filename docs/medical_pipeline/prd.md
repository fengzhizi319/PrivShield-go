# 医疗敏感数据全流程治理流水线 — 产品需求文档 (PRD)

---

## 1. 背景与目标

### 1.1 业务背景
在医疗健康大数据共享、医保跨域结算及康养评估辅助决策场景中，电子病历、处方流转与体征监测数据混杂了大量个人身份信息（PII，如身份证、医保卡、联系方式）以及国家法规重点监管的特高敏感级病史（L4/L5 级，如艾滋病 HIV、恶性肿瘤、精神障碍、传染病、遗传缺陷等）。传统单一掩码脱敏容易遗漏非结构化病历文本中的高危临床实体，无法满足国家医疗健康数据安全标准。

### 1.2 核心目标
1. **仿真医疗数据自动生成**: 提供数据生成脚本，生成符合 GB 11643-1999 校验码的真实身份证、规范 ICD-10 编码及 L4/L5 敏感病史样本。
2. **端到端医疗治理流水线**: 基于 Go 原生高性能架构，集成医保 19 与康养 27 字段特化映射、3-Layer 分类分级、L4/L5 重症强脱敏与 DICOM 影像元数据清洗。
3. **双结构合规保障**: 治理过程同步输出 (1) 分类分级元数据报告 (`classification_report`) 与 (2) 100% 剥离 L4/L5 原始高危词汇并完成 PII 脱敏的安全数据集 (`sanitized_data`)。
4. **语法自愈与数据可用性**: 脱敏后自动自愈临床断句残渣，消除孤立逗号/顿号，确保下游临床科研与统计分析可用。
5. **高性能并发吞吐**: 多核无锁分块并发处理，支持 **≥ 80,000 条/秒** 批量脱敏吞吐。

## 3. 功能需求矩阵

### 3.1 算法与数据治理需求 (F-1)
- **F-1.1 动态别名映射**: 支持中英文别名映射（如“居民身份证”、“sfz”、“id_card”自动映射至 `id_card_no`）。
- **F-1.2 L4/L5 强剥离**: 包含 HIV、恶性肿瘤、重度抑郁/精神分裂、梅毒、乙肝、尿毒症等 40+ 类重大高危病史词库的绝对抹平与标准化范畴替换。
- **F-1.3 语法自愈引擎**: 抹除敏感短语后，自动修复破损句式（如 `患者入院，，诊断为` $\rightarrow$ `患者入院，诊断为`）。
- **F-1.4 ICD-10 编码治理**: 精准识别 `B20-B24` (HIV)、`C00-C97` (恶性肿瘤)、`F20-F29` (精神分裂) 等高危区间并泛化至大类。
- **F-1.5 DICOM 影像元数据清洗**: 二进制解析 DICOM 文件，抹平患者姓名、出生日期、检查编号与机构信息，支持白名单安全沙箱。

### 3.2 接口与全栈集成需求 (F-2)
- **F-2.1 REST API**: 暴露 `POST /v1/medical/process`、`POST /v1/medical/sanitize` 及 `POST /v1/medical/sanitize/batch`。
- **F-2.2 Go BFF 代理**: `console/bff-go` 暴露 `POST /api/medical_pipeline`，支持无缝加载预置样例与自定义上传。
- **F-2.3 控制台可视化**: 前端 `MedicalPipelinePanel.tsx` 支持双结构报告左右分栏对比、敏感等级图谱与高危命中标识。

## 4. 验收标准

1. **身份证合规验证**: 所有生成的身份证号 100% 通过 GB 11643-1999 校验码计算。
2. **零 L4/L5 高危词汇泄露**: 治理后 `sanitized_data` 中 100% 不存在原始高危临床病史明文。
3. **单元测试 100% PASS**: `go test ./privacy-go-sdk/medical/...` 与 `go test ./engine-go/internal/imageredact/...` 全量通过。
4. **端到端集成通过**: 通过控制台或 cURL 调用 `/v1/medical/process` 能秒级完成 100 条记录的全流程治理。
